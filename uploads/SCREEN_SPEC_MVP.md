# 화면 명세서 + MVP 범위 (Screen Spec & MVP Scope)

*가치의 역전 — 텍스트 기반 Extraction 서바이벌*
UI 구조·흐름 명세 (2026-07-08)

> **이 문서의 목적**: "유저가 무슨 화면을 보고, 각 화면에 무엇이 있으며, 어디로 이어지는가"를 정의한다. **클로드 디자인의 입력 문서**로, 여기서 디자인 시스템(컬러·타이포·컴포넌트)과 와이어프레임이 도출된다.
> **역할 분리**: 시스템 로직·공식 = `DEV_HANDOFF.md` / 컨셉·철학 = `Game_Concept_v2` / 데이터 = 구글 시트(RL_*) / **화면·흐름 = 이 문서**.
> ⚠️ 이 문서는 화면의 **구조·내용·톤 방향**까지만 정한다. 실제 색·폰트·컴포넌트 스타일은 다음 단계(클로드 디자인)에서 확정한다.

## 0. 제작 플랜에서의 위치

```
[완료] 컨셉 문서 · 개발 핸드오프 · 데이터 시트
   │
0단계 ▶ 화면 명세서 (이 문서)          ← 지금
   │
1단계 ▶ 클로드 디자인: 디자인 시스템 + 와이어프레임
   │

   │
3단계 ▶ 클로드 코드: 개발 · 플레이 테스트
```

## 1. 디자인 방향 (톤 & 무드)

*다음 단계 디자인 시스템의 방향성. 실제 토큰은 클로드 디자인에서 확정.*

- **핵심 컨셉**: 겉보기엔 **일상 앱**처럼 보이는 UI — 생산성 앱 × 파이낸스 앱의 톤. 화려한 게임 UI가 아니라, 자산·수치·목록을 담담하게 관리하는 느낌.
- **분위기**: 냉혹하고 현실적인 근미래 아포칼립스. 불신과 고독. 과잉 연출 없이 정보 중심.
- **핵심 화면 특성**: 텍스트 로그 기반 게임이므로 **가독성 높은 타이포**와 **로그의 리듬**이 UX의 중심.
- **플랫폼**: 모바일 우선(세로), 이후 확장 고려.

## 2. MVP 범위 (1차 테스트에 넣을 것 / 뺄 것)

**MVP의 목표**: 핵심 재미 루프 — *출정 → 자동 전투 → 전리품 → 성장 → 장비 강화 → 다시 출정* — 가 실제로 돌고 재미있는지, 그리고 잠정 밸런스 수치가 적절한지 검증한다.

### ✅ MVP에 포함 (핵심 루프)
- 안전가옥 허브 / 존 선택(도시 1개 + 존 몇 개) / **자동 전투(전 공식 실작동: 명중·데미지·방어·크리·상태이상)** / 출정 결과(전리품·사망 처리)
- 인벤토리 + 장비 착용(무기·방어구·아티팩트) / 캐릭터(1차·2차 스탯·성장 현황)
- 상점(소모품 중심 — 보건소·급식소) / 장비 수리(내구도, 익스트랙션 리스크의 핵심)
- 스태미너·생명력 자원, 사망 시 손실·랜덤 내구도 감소

### ❌ MVP에서 제외 (검증 후 확장)
- 애장품 패시브 / 재질 상성 / 퀘스트 시스템 / 전당포 감정 / 히든 존
- 암시장·전당포·철물점(상점 확장) / 다중 도시 / 접사(Affix) 세부 롤링 / 장비 강화(Enhance)

> 원칙: **핵심 루프가 재미있는지 먼저 확인** → 검증되면 부가 시스템을 붙인다. 밸런스가 전부 잠정치이므로 MVP 플레이 테스트가 수치 조정의 출발점이다.

## 5. 화면별 명세

각 화면: **목적 / 핵심 요소 / 표시 데이터(참조 시트) / 전이 / 주요 인터랙션**

### S1. 타이틀 / 로그인
- **목적**: 게임 진입. (MVP는 최소 구성)
- **핵심 요소**: 게임 타이틀, 시작 버튼(이어하기/새로하기).
- **데이터**: 저장 데이터(세이브 유무).
- **전이**: → S2.

### S2. 안전가옥 (허브) — *중심 화면*
- **목적**: 모든 활동의 출발점. 준비 → 출정 → 귀환의 거점.
- **핵심 요소**: 캐릭터 요약(생명력·스태미너·사토 잔액), 메뉴 진입(출정/상점/인벤토리/캐릭터/수리/애장품), 현재 출정 카운터(재고 리셋 주기 표시).
- **데이터**: 캐릭터 상태(저장), 사토(저장), 스태미너(저장), shop_stock_reset_interval(Config).
- **전이**: → S3(출정) / S6 / S7 / S8 / S9 / (S10).
- **인터랙션**: 각 메뉴 탭 진입. 스태미너/생명력 회복은 상점(소모품)에서 처리.

### S3. 존 선택
- **목적**: 어디로 출정할지 선택.
- **핵심 요소**: 도시 목록(난이도 티어), 존 목록, 히든 존(잠금 표시·해제 조건), 존별 전리품 성향(LootFocus), 출정 시작 버튼.
- **데이터**: RL_City, RL_Zone(IsHidden·UnlockType·UnlockKey).
- **전이**: → S4(출정 시작) / ← S2(취소).
- **인터랙션**: 존 선택 → 확인 → 전투 진입. (히든 존은 조건 미충족 시 잠금.)

### S4. 전투 (로그) — *핵심 화면*
- **목적**: 텍스트 자동 전투. 이 게임의 심장.
- **핵심 요소**: **전투 로그(스크롤)**, 플레이어 HP/스태미너 바, 몬스터 정보(HP·이름·등급), 상태이상 표시(양측), 전투 제한 시간.
- **데이터**: RL_Monster(스탯·등급·상태이상), 전투 공식 전체(DEV_HANDOFF), RL_StatusEffect, RL_Weapon/Armor(착용 장비), 출정 지참 인벤토리(저장).
- **전투 진행**: 전투는 **자동으로 진행**되며 유저의 실시간 개입은 없다(로그만 출력). 유저의 판단은 **전투와 전투 사이**에서만 이루어진다.
- **전투 사이 결정 UI (3버튼)**: 각 전투 종료 후 다음이 표시된다 — **[다음 전투 계속] / [회복하기] / [귀환·도망]**.
  - **다음 전투 계속** → 다음 몬스터와 전투(S4 반복). 전투가 길어질수록 희귀 몬스터 확률↑, 자원 소모↑.
  - **회복하기** → 회복 서브플로우(아래)로 진입. 회복 후 다시 이 3버튼으로 돌아와 반복 가능.
  - **귀환·도망** → 출정 종료(→ S5). **도망 성공 확률(기본값)은 화면에 표시하지 않는다**(긴장감). 성공/실패는 실행 후 판명.
- **회복 서브플로우**: [회복하기] → **출정 시 지참한 인벤토리의 음식·회복 아이템 리스트**(⚠️ 안전가옥 보관 아이템과 별개) → 아이템 선택·사용 → 다시 전투 사이 결정 UI(3버튼). 여러 번 반복 가능.
- **전이**: [계속] → S4 / [귀환·도망] → S5 / 사망 → S5 / 시간 초과 → 판정.
- **핵심 설계 포인트**: 소모품은 **출정 지참분에서만** 사용 가능 → "출정 전 무엇을 챙길지"가 전략이 된다. 전투 중이 아닌 **사이사이 판단**이 이 게임의 리듬.

### S5. 출정 결과
- **목적**: 출정 성과 정산.
- **핵심 요소**: 획득 전리품 목록, 획득 사토(있으면), 성장한 스탯 요약. **사망 시**: 전리품·지참 소모품 손실 표시, 랜덤 장비 내구도 감소(파괴 시 알림).
- **데이터**: LootTable 결과(저장), 성장 델타, 내구도 변화.
- **전이**: → S2.
- **인터랙션**: 결과 확인 → 안전가옥 복귀.

### S6. 상점
- **목적**: 소모품 구매·전리품 판매(사토 전환).
- **핵심 요소**: Vendor 선택(이름·상점 성격 ShopType), 구매 목록(가격·재고 StockMax), 판매(보유 아이템 중 **거래 카테고리에 맞는 것만** 노출), 사토 잔액.
- **데이터**: RL_Vendor(ShopType·TradeCategories·ShopID), RL_Shop(BuyPrice·StockMax), RL_Item(SellPrice=매입가).
- **전이**: ⇄ S2.
- **인터랙션**: **카테고리 게이팅** — 아이템 Category가 상점 TradeCategories에 포함될 때만 거래. 재고는 출정 N회마다 리셋.
- **MVP**: 보건소(약품)·급식소(음식)만. 나머지 Vendor는 확장.

### S7. 인벤토리
- **목적**: 아이템 관리·장비 착용.
- **핵심 요소**: 아이템 목록(카테고리별), 장비 슬롯(무기/투구/갑옷/아티팩트 착장·소지), 내구도 표시, 아이템 상세(스탯·태그).
- **데이터**: RL_Item/Weapon/Armor/Artifact, 보유·착용 상태(저장).
- **전이**: ⇄ S2.
- **인터랙션**: 착용/해제 → 캐릭터 스탯에 즉시 반영. 성장 태그·부여력·저항 등 표시.

### S8. 캐릭터
- **목적**: 성장 현황·스탯 확인.
- **핵심 요소**: 1차 스탯(힘·민첩·체력·의지)과 각 성장 진행도(트리거 카운트/다음 요구치), 2차 스탯 최종값(장비 반영), 착용 장비의 성장 태그 요약.
- **데이터**: RL_PrimaryStat(트리거·GrowthPointPerTrigger), RL_SecondaryStat(파생·base·cap), RL_Config(A·r·태그배율), 누적 성장(저장).
- **전이**: ⇄ S2.
- **인터랙션**: 성장은 전투 중 자동. 이 화면은 열람 위주.

### S9. 장비 수리
- **목적**: 내구도 회복(익스트랙션 리스크 관리).
- **핵심 요소**: 장비별 현재/최대 내구도, 수리 비용(사토), **수리 시 최대 내구도 영구 감소** 경고.
- **데이터**: 장비 내구도(저장), 사토(저장).
- **전이**: ⇄ S2.
- **인터랙션**: 수리 실행 → 내구도 회복 + 최대 내구도 소량 영구 감소. (강화 Enhance는 MVP 제외.)

### S10. 애장품 등록 *(MVP 이후)*
- **목적**: 안전가옥 등록 슬롯(1개)에 애장품 등록 → 지속 패시브.
- **핵심 요소**: 등록 슬롯, 교체 시 내구도 소모 경고.
- **데이터**: RL_Item(애장품 카테고리), 패시브 효과(추후 설계).
- **비고**: 전체 패시브 시스템 설계 후 반영.

## 7. 다음 단계 인계 사항 (클로드 디자인용)

- 이 문서의 **1. 디자인 방향**을 톤 기준으로 삼아 디자인 시스템(컬러·타이포·컴포넌트) 도출.
- 필요 컴포넌트(예상): 로그 뷰, 스탯/자원 바, 아이템 카드, 목록/리스트, 탭 내비게이션, 확인 다이얼로그(수리·사망 등).
- 우선 와이어프레임 대상: **MVP ✅ 화면(S1~S9)**. 특히 **S2 허브 · S4 전투**가 핵심.
- 확정: 소모품은 전투 사이 [회복하기]로만 사용(출정 지참분 한정), 도망 확률은 비표시. (S4 참조)
